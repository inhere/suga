## 目标

目标是提供启动时固定的 `zh`/`en` UI 语言选择：顶层 `language`，默认 `auto`，`SUGA_LANGUAGE > config.language > auto`；`auto` 在 Unix/macOS 读 locale、Windows 读用户 locale；中英常见别名读取时归一化，写入规范值。阶段 1 只迁移人类 UI，阶段 1b 只做约十条模型侧英文最小集并以真实 provider 对照评测验收。

## 范围

**Scope freeze：**设计 0.4 的 D1–D8、阶段 1/1b 范围与 §ACP/stream-json/Gofer 边界；停止条件是出现 Semantic Amendment、Ownership Conflict，或需要改协议契约/扩大模型侧翻译范围。评审为 SR1409 单轮，当前无阻断发现。

排除：不翻译 JSON/ACP/stream-json/Gofer 机器字段、工具名、命令名、error code、trace 稳定事实标记；不让 `pkg/agentcore` 依赖 `internal/i18n`；不做运行时热切换、locale 格式化、`suga-guide` 全量英文版、系统提示/工具 description 的整体翻译；不修改设计、研究、历史 CHANGELOG；本任务阶段计划不实施任何代码。`host_or_non_offline_action=REQUIRED`：阶段 1b 需要真实 provider 与监督方 Linux PTY，但这些是后续人工 Gate。


## 完成定义与总 Gate

1. `internal/i18n` 为薄门面，使用 gookit/i18n v1.3.0 实例 API、`embed.FS`、`DirMode`（每语言一个目录、按区域分文件：`catalog/{en,zh}/<area>.ini`）、`ReplaceMode` 命名占位符；`en` 是 canonical，`zh` 逐文件 key/placeholder parity；缺词条英文回退并一次 warning。

> 与设计的差异（0.2）：设计 §2 写“每种语言一个 `catalog/<lang>.ini`（FileMode）”。计划改用 gookit 的 `DirMode` 按区域分文件（`chat_approval.ini`、`chat_commands.ini`、`chat_status.ini`、`cli.ini`、`personal.ini`、`host.ini`…），让 T4–T9 并行时各改各的文件、不在同一文件上冲突；key 仍是全局唯一的点分名，parity 测试按文件比对。属实现细节，不改设计的决策 D1–D8，随本计划一并请用户确认。
2. 配置真实路径支持 `language`、别名归一、环境覆盖、`get/set/unset/list` 的 effective value/source；`inspect manifest` 显示 resolved language 与 source。
3. 阶段 1 的 chat、CLI、personal 用户可见状态、wiring/ACP server/output/clipboardimage 展示层按包迁移；`language: zh` 原文兼容，`en` 新增断言；agentcore 模型侧保持稳定。
4. 现有 ptysmoke/ptye2e 固定 `language: zh`，新增英文 PTY/Go 场景覆盖 banner、审批、状态、`:help`、config set；每个交互批次监督在 Linux 跑 `make smoke-chat` 与相关 ptye2e，并做反向验证。
5. 阶段 1b 候选逐条评估并实现后，`zh` 请求逐字节快照不变；真实模型 `opencode-go/deepseek-v4.1-flash` 或 codex，`en`/`zh` 各跑难版长会话与带审批工具任务 `--repeat 3`，通过率和 `steady` 桶命中率不退化后才完成。
6. README（中英）、`config/config.yaml`、suga-guide 配置参考、CHANGELOG 完成对应文档更新；CHANGELOG 只在未发布段新增一条。

## 前置检查与 fail-closed 条件

实施分支开始前：确认 Git root、`core.worktree` 为空、工作区只含实施方文件；重新核对 gookit/i18n v1.3.0 API、MIT 许可及 `go.mod`/`go.sum` 现状。运行 `gofer job show $GOFER_JOB_ID`/配置隔离检查，所有真实 provider 与 PTY 场景使用隔离 `SUGA_HOME`。

Fail-closed：

- 未设置 `language` 或解析为 `auto` 时，中文 locale 仍为 zh，未知/非中文为 en；显式 `language: zh` 的既有文本必须保持。
- `SUGA_LANGUAGE` 非空非法、配置非法、alias 无法归一均启动/命令报错，不静默写入或回退。
- catalog key/placeholder parity、英文 fallback warning、来源显示失败即停止，不继续迁移 UI。
- `pkg/agentcore` 不得 import `internal/i18n`；ACP/stream-json/Gofer 结构与稳定文本 golden 不变。
- 阶段 1 不得改变模型请求；阶段 1b `zh` 请求快照不逐字节一致则停止，不宣称完成。
- Linux ptysmoke 反向验证失败、真实模型通过率或 steady 命中率退化，则不合入默认行为，保留已提交的可回滚批次并请求决策。

## T0 结论（实施细则，0.3）

依据 `docs/research/2026-10-27-i18n-t0-baseline.md`，以下细则对 T1–T15 有约束力：

1. **catalog 规则（T1 固化，T4–T9 遵守）**：INI section 名就是 key 首段（写 `[chat]` + `approval.allow = …`，取 `chat.approval.allow`；不能写 `[chat.approval]`，也不能写无 section 的点分键）；跨文件同 key 会被 gookit 静默覆盖，T1 提供“重复 key 检测”测试；多行文案在 ini 中写字面 `\n`，由门面 `T()` 统一转为换行；值禁止出现 `${`（ini 默认展开环境变量），测试断言；文案以引号开头/结尾时需额外处理。
2. **门面**：调 `Tr` 前校验语言已注册（只认 `zh`/`en`）；缺失判断用 `HasKey` + 数据枚举，不用 `Tr` 的输出；parity 用 `Lang(lang).Data()` 拼 `section.key` 逐文件比对。
3. **Windows**：按批准的“用户 locale”实现——先 `kernel32` `GetUserDefaultLocaleName`（LazyProc，T0 已实测可用），失败再用 `x/sys/windows.GetUserPreferredUILanguages(MUI_LANGUAGE_NAME)` 第一项；都失败选 `en`。文件带 `//go:build windows`。
4. **config**：`config get/list language` 显示规范值（`auto`/`zh`/`en`）与 source；解析后的实际语言由 manifest 显示（T3）。接线点见 T0 报告 §3（含 `effectiveConfigValue` 必须加显式 case、`main_test.go` 清理 `SUGA_LANGUAGE`、参考配置叶子测试）。
5. **任务文件归属**：以 T0 报告 §6 为准，重叠按 §6.7：`internal/wiring/chat_approver.go` 归 T4；`internal/chat/render.go` 归 T4 且 **T4 先拆分**（现 1004 行，超 1000 行上限）再迁移；`layout.go`、`tool_summary.go`、`steering.go` 归 T6；`chat_commands.go` 归 T5；`memory_runtime.go` 与 `acpserver/memory_confirm.go` 都归 T9；“输出被截断”文案以 `internal/output` 为宿主。
6. **T8 工作量下调**：personal 可迁移的 A 类约 20 行（`cwd.go`、`store/usage.go`、`recovery.go`、`replay.go`、`outschema/contract.go`），其余时间写 B 类不被改写的快照测试。
7. **1b 候选（T14）共 8 条**：原 1–7 不变；原第 8 条删除（`prompt.go` 无中文提示文本）；原第 9 条只保留 `internal/chat/hooks_gate.go:56,61,63` 的 hook 拒绝理由，`[来自 …]` 来源标签属来源/注入标记，按设计不翻译。
8. **gofmt**：用 `gofmt -l .`（Windows 上 `$(git ls-files)` 会参数过长且误报通过）。

## 回滚

每个任务独立 conventional commit，只 add 该任务文件；提交前 `git status --short`、`git diff --cached --name-only`、`git diff --stat`，不 push、不 tag、不改 `.gofer/tracker`。按任务 `git revert <commit>` 可回滚；阶段 1 默认 `language: auto` 的行为变化可由配置显式 `language: zh` 回退，catalog/host 迁移可按波次回退。阶段 1b 若评测退化，只回退 T14/T15，不回退已验证的 zh UI 阶段；不切换默认模型文字行为，直到用户批准。

## 人工 Gates

1. 用户批准本计划 Draft 0.1 后才可实施。
2. T0 若依赖 API、Windows locale、配置 descriptor 或分层事实与设计不符，先停并请求修订。
3. 阶段 1 合并前监督在 Linux 跑全量 `make smoke-chat`、相关 ptye2e 并完成反向验证；本 Windows job 不声称已运行 PTY。
4. 阶段 1b 真实模型结果（`en`/`zh`、`--repeat 3`、steady 分桶）交用户审阅；通过率/命中率不退化且用户再次批准后才合并默认行为。
5. push、tag、发版及内网上传均不在本计划授权内。

## 完成 Gate

完成定义见“目标”与“总 Gate”。阶段 1 的完成 Gate 是 T13 全部构建、测试、静态检查及监督 Linux smoke/pty 通过，并由用户批准合并；阶段 1b 的完成 Gate 是 T14 快照与分层通过、T15 真实 provider `--repeat 3` 的 en/zh 通过率和 steady 桶命中率不退化，并由用户审阅评测结果后批准。失败时保留已验证提交，按波次回滚，不宣称阶段完成。
