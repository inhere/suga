## 背景

第四十五批 A（`aa3ce473`）加了前缀复用率、续接与切换分桶、换段分节哈希，只改统计、请求字节不变。E2 用 `opencode-go/deepseek-v4.1-flash` 跑三个难版长会话任务，各 3 轮（`tmp/eval/b45-*`，2026-10-27）：

| 桶 | rule-update 命中 / 复用 | distractor-rules | naming-rules |
|---|---|---|---|
| steady（段内） | 88.1% / 100% | 82.5% / 100% | 93.0% / 100% |
| resume_same（续接、前缀未变） | 80.9% / 90.6% | 87.5% / 100% | 69.8% / 79.4% |
| segment_start（换段后第一次） | 71.4% / 100% | 69.1% / 99.4% | 62.1% / 92.3% |
| **handoff（写交接包）** | **2.4%** | **0.7%** | **0.4%** |
| 总体 | 79.4% | 79.9% | 83.6% |
| 通过 | 3/3 | 3/3 | 2/3 |

读法：

1. 段内前缀复用率三组都是 100%：上一次能复用的都复用上了，命中率低于 95% 只因为每轮有新内容。95% 目标按复用率已经达到。
2. 续接时复用率 79–100%：前缀没变，缺口是 provider 侧缓存冷了，suga 改不了。
3. 换段时段上下文里**只有交接包一节变化**（13 次换段全部如此），记忆索引等其他节没变。“按变化频率重排段上下文”在评测里没有收益，暂不做（日常使用中记忆会变，留待真实会话数据再看）。
4. 写交接包的调用几乎不命中：它用独立的系统提示（`compactSystemPrompt`）和一条重新渲染的对话文本（`compact.go` `summarize` / `summaryCall`），与会话前缀完全不同。每次 6k–11k token 全价输入，是现在最大的可省部分。

## 范围与非目标

范围：换段时生成交接包的那次调用（`segment_handoff.go` → `summarize`，scenario `compact`）。

非目标：跨会话交接（`handoff.go`，`suga handoff`）、空闲压缩（scenario `idle`）、段上下文重排、交接包格式与预算（`compactTemplate`、`normalizeHandoffBody` 不变）。

## 已确认事实

- `summarize` 把被压缩部分渲染成文本（`renderTranscript`，单条上限 4000 字符并逐次减半），加上模板、上一份交接包、计划、最近请求、候选引用，作为唯一一条 user 消息；系统提示是 `compactSystemPrompt`，不带工具（`compact.go:536-600`）。
- 交接包调用的 provider 是 `compactProvider()`：配置了 `CompactProvider` 时用它，否则用主 provider（`compact.go:467`）。
- agentcore 已有 `GenerateRequest.ToolChoice = ToolChoiceNone`，并能判断 provider 是否支持（`pkg/agentcore/runtime_wrapup.go:95-110`、`supportsToolChoice`）。
- 统计层会把交接包调用记为 `handoff` 桶（purpose compact），不影响主循环的前缀跟踪。
- **`tool_choice: none` 会改变渲染出来的提示（H5，2026-10-27 实测）**：同一份请求（system + 24.6 KB 工具表 + 3 条消息）对 `opencode-go/deepseek-v4.1-flash` 依次发送——不带 tool_choice 两次：`prompt_tokens=8394`，第二次 `cached=8320`；同样内容加 `tool_choice: none`：`prompt_tokens=2204`（工具定义没进提示）、`cached=384`；只追加一条 user 消息、不带 tool_choice：`prompt_tokens=8402`、`cached=8320`。所以第四十五批预跑里沿用调用输入少约 4.5k、缓存读取为 0 的原因是 `ToolChoice=ToolChoiceNone`，不是网关不支持前缀缓存。结论：沿用调用只发 System/Tools/Messages，不发 ToolChoice，靠指令约束；回答带工具调用时按 `handoffFallbackToolCall` 回退。其他 provider 无法预先判断它们是否也这样渲染，统一不发。

## 方案

换段时，若满足“可沿用条件”，交接包请求改为：

```
System   = 本段主循环最后一次请求的 System（逐字节相同）
Tools    = 同上（逐字节相同），ToolChoice 不发（H5：`none` 会让网关丢掉工具定义、前缀缓存不命中）
Messages = 同上的全部消息（本段到此为止的对话，含将保留的尾部）
         + 1 条新的 user 消息：交接指令
```

交接指令 = 现有 `compactTemplate` + 上一份交接包 + 计划 + 最近请求 + 候选引用（与现在相同），去掉“待压缩的对话”文本，改为一句说明：“只概括从本段开头到倒数第 N 条消息之前的内容；最后 N 条会原样保留，不要写进交接包；不要调用工具，不要继续当前任务，只输出交接包。”

这样请求的前缀与上一次主循环请求一致，只有末尾的指令是新的，预计命中率接近段内调用。

**可沿用条件**（任一不满足就走现有路径，行为与现在完全相同）：

1. 交接包调用的 provider 与主循环同一个模型（没有另配 `CompactProvider`，或另配的就是同一模型）。不同模型的缓存不互通，沿用前缀没有意义。
2. 估算请求大小（当前上下文 + 指令 + 输出预留）不超过模型窗口。换段阈值低于窗口，正常都满足；接近窗口时回退。
3. 能拿到本段最后一次主循环请求（Runner 回合内持有；拿不到就回退）。

**结果校验与回退**（新路径专有）：

- 回答里带工具调用、为空、或缺少交接包的必需小节 → 丢弃，按现有路径重做一次（多花一次调用，但不会产出坏的交接包）。
- 输出被截断 → 与现在一样，补一句预算说明再要一次（仍走新路径）。
- 回退次数记进 trace（`handoff_reuse=fallback:<原因>`），`--analyze` 与评测汇总显示。

**开关**：新增设置 `compact.handoff_reuse_prefix`（默认 `true`，评测通过后才合入），`false` 时完全走现有路径，作回滚手段。

## 预期收益与代价

- 输入成本：现在每次 6k–11k token 全价；改后请求变大（整段上下文约 11k–17k token），但绝大部分按缓存价计，未缓存的只有指令约 2k–3k token。缓存价按 provider 不同约为全价的 1/10 到 1/4（各 provider 未逐一核实），总体预计交接包这一步的输入花费降到一半以下。
- 延迟：预填充命中缓存，预计更快；未实测。
- 质量：模型看到的是完整对话（含完整工具输出）而不是截断后的文本，交接包可能更准，也可能更长。由预算与 `normalizeHandoffBody` 兜住长度；准确性靠下面的回归评测判断。
- 风险：主系统提示下模型可能“继续干活”而不是写交接包 → 指令约束（不发 ToolChoice）+ 必需小节校验 + 回退。

## 验收

- 单测：可沿用条件四种回退、工具调用回退、缺小节回退、截断重要、开关关闭时请求与现在逐字节相同（复用 A 的录请求写法）。
- 评测：三个难版长会话任务，`handoff_reuse_prefix` 开 / 关两个 variant **交替运行**（避免顺序带来的缓存偏差），各 3 轮：
  - 通过率不低于关闭时；
  - handoff 桶命中率 ≥ 80%，回退次数为 0 或个位数且原因可解释；
  - 原话约束、保护小节的检查项结果与关闭时一致；
  - 交接包平均长度不超过关闭时的 1.3 倍。
- 冒烟与 ptye2e 全过。

## 决策

| # | 决策 | 依据 |
|---|---|---|
| H1 | 只改换段交接包这一次调用，跨会话交接与空闲压缩不动 | 数据只覆盖换段；范围最小 |
| H2 | 不满足可沿用条件就走现有路径，结果校验失败回退现有路径重做 | 不让新路径产出坏交接包 |
| H3 | 段上下文暂不重排 | 13 次换段只有交接包一节变化 |

## 待确认事项

结论（2026-10-27 用户按推荐批准）：1 默认 `true`；2 另配不同压缩模型时走现有路径；3 按推荐预算评测。

1. 开关默认值：推荐评测通过后默认 `true`，保留设置作回滚。
2. 另配了不同的压缩模型（`CompactProvider`）时：推荐直接走现有路径（不尝试沿用）。
3. 评测预算：推荐 3 任务 × 2 variant × 3 轮交替，约 2–3 小时主机时间。

## 风险与回滚

- 回滚：设置 `compact.handoff_reuse_prefix: false`，或回退该提交；交接包格式与存储不变，无数据迁移。
- 若评测显示质量下降：保留统计与开关代码，默认值改为 `false`，在研究文档记录原因。
