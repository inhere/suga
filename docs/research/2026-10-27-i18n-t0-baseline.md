1. **依赖可用**：`github.com/gookit/i18n v1.3.0`（MIT，2026-10-26 发布，是当前最新版）可离线取得；它要求的 `gookit/goutil v0.8.3`、`gookit/ini/v2 v2.3.2` 与本仓库现有版本**完全一致**，其余间接依赖本仓库版本都更高，加它不会升级或降级任何现有模块。`DirMode + embed.FS` 在本机 Windows 上实测能加载每个语言目录下的多个 `*.ini` 并取到 key。

6. **基线全绿**：`go build` / `go vet` / `gofmt` / `staticcheck` / `go test -count=1 ./internal/... ./pkg/...` 全部 exit 0、无失败项。

### 1.5 实施约束（T1 必须按此写，否则词条取不到）

1. **点分 key 只有“首段 = INI section 名”能解析**。`ini.GetValue` 用 `SplitN(key, ".", 2)` 切 section 与 key（`ini@v2.3.2/manage.go:38`、`ini.go:335-347`）。实测：
   - `[chat_approval]` + `title = …` → `chat_approval.title` ✅（1a）
   - `[chat_approval]` + `nested.deep.key = …` → `chat_approval.nested.deep.key` ✅（6c，section 内剩下的点保留原样）
   - `[chat_approval.shared]` + `only-en = …` → `chat_approval.shared.only-en` ❌（first 段是 `chat_approval`，第二段 `shared.only-en` 找不到 → 返回 key）
   - 无 section 的 flat 点分键 `chat_approval.title = v` → ❌（落在 `__default` section 里，且 `HasKey` 也是 false）
   → 设计 §词条组织 的 `chat.approval.allow` 形状**可用**，但 catalog 文件必须写成 `[chat]` section + `approval.allow = …`；**不能**写 `[chat.approval]`。建议 T1 在 catalog 文件头注释里固定这条规则，并让 parity 测试按“section.key”拼名（第 8 条方式）比对。
2. **跨文件同 section 同 key 静默覆盖**（第 2 条）。T4–T9 各改各的 `catalog/*/<area>.ini`，一旦两人给同一 key 赋值不会报错，只会按文件名字典序取后者。建议 T1 增加“重复 key 检测”测试（把所有 area 文件先自己解析一遍，重复即 fail），而不是只依赖 gookit。
3. **`Tr` 在“值存在但为空”时返回 key 而不是空串**（6a），而 `HasKey` 是 true。parity/缺失告警必须用 `HasKey`+`Data()` 判空值，不能用 `Tr` 的输出判断。
4. **未注册语言会静默回退到英文并渲染参数**（4e），`HasLang`/`HasKey` 都是 false。门面必须在调 `Tr` 前校验解析出的语言已注册（`zh`/`en`），否则配置非法时用户会静默看到英文。
5. **值里的 `\n` 不会变成换行**（9 `probe.multiline` = `"第一行\\n第二行"` 字面量反斜杠 n）。`:help`/`:usage`/审批多行说明（`internal/chat/chat_usage.go` 是最大中文源，95 行）需要二选一：门面的 `T()` 对该 key 做 `strings.ReplaceAll(v, "\\n", "\n")`，或一条文案拆成多 key 由调用方逐行输出。`ini.ReplaceNl` 选项无法通过 `i18n` 开启（`i18n` 用 `ini.New()` 自建实例，`options.go:49-73` 的 setter 只在 `NewWithOptions` 生效）。
6. **值里出现 `${VAR}` 会被环境变量替换**（6d）——这是 `ini.ParseEnv` 默认 true 的副作用。catalog 值禁止写 `${…}`；建议 parity 测试顺手断言值里不含 `${`。
7. 其他字符安全（不必转义）：行内 `#`、`;`、`:`、`=`、`[]`、`%` 都保留原样；但值用双引号包裹时引号会被去掉（9 `probe.quote`），所以只有当文案本身要以引号开头/结尾时才需要额外处理。
8. **性能/并发**：i18n 未暴露 `ini.Readonly`，每次 `Tr`/`HasKey` 都要拿 `ini.Ini` 的写锁（`manage.go:27-31`）。只读场景安全，但热路径（状态行每帧渲染）会有锁竞争；建议门面缓存“key→已渲染值”仅当无参数时，或接受串行化并在 T6 的状态行批量渲染里避免逐字调用。

| flags 常量 | `MUI_LANGUAGE_NAME = 0x8`（返回 BCP-47 名，如 `zh-CN`）、`MUI_LANGUAGE_ID = 0x4`（返回 `0804` 这种十六进制 LANGID 字符串） | `x/sys@v0.49.0/windows/types_windows.go:2725-2726` |
| 本机实测 | `GetUserPreferredUILanguages(MUI_LANGUAGE_NAME) = [zh-CN en-US]`、`GetSystemPreferredUILanguages(...) = [zh-CN en-US]`、`GetUserDefaultLocaleName(LazyProc) = "zh-CN"`、`GetUserDefaultUILanguage = 0x0804` | 临时程序 `tmp/localeprobe`（已删除），见下 |

实测原始输出：

```text
GetUserPreferredUILanguages(MUI_LANGUAGE_NAME) = [zh-CN en-US] err=<nil>
GetUserPreferredUILanguages(MUI_LANGUAGE_ID)   = [0804 0409] err=<nil>
GetSystemPreferredUILanguages(MUI_LANGUAGE_NAME) = [zh-CN en-US] err=<nil>
GetUserDefaultLocaleName(LazyProc) = "zh-CN" ret=6 err=The operation completed successfully.

```

`GetUserDefaultLocaleName` 的 LazyProc 调用方式（若 T1 仍需要“用户 locale 名称”而不是“首选 UI 语言列表”）：

```go
proc := windows.NewLazySystemDLL("kernel32.dll").NewProc("GetUserDefaultLocaleName")
buf := make([]uint16, 85) // LOCALE_NAME_MAX_LENGTH
n, _, err := proc.Call(uintptr(unsafe.Pointer(&buf[0])), uintptr(len(buf)))
name := windows.UTF16ToString(buf) // n 为含结尾 NUL 的字符数，0 表示失败
```

**建议 T1**：`locale_windows.go` 用 `GetUserPreferredUILanguages(windows.MUI_LANGUAGE_NAME)` 取第一个元素，`strings.HasPrefix(lower, "zh")` → `zh`，否则 `en`；出错或空列表 → `en`（符合设计“未知/不可读 locale 选 en”）。这样不需要 `unsafe`、不需要 LazyProc，也不需要 `syscall`。注意它是**无构建标签也必须 Windows 才能编译**的 API，所以文件必须带 `//go:build windows`，并在 Unix 侧提供 `locale_unix.go`（`LC_ALL > LC_MESSAGES > LANG`）。
